# Mirror the participant-flow rules in packages/mobile-tiktok

## Decision

`packages/mobile-tiktok` is a standalone TypeScript app built by Vite for the `safari12` target that re-implements the participant-flow rules the Python runtime enforces, in its own modules, because none of the Python-runtime records route to it.

## Guidance

- Nothing but `app-loaded`, `initialized`, `resize` and fixed-vocabulary `CommandSystemLog` milestones may cross to the host before the participant presses Donate; the donated payload is the only thing that carries data, and an error report is a separately consented donation under the `error-report` key that carries a category, app version, user agent and timestamp, never a trace or a value from the archive.
- Reject the picked file on `File.size` before reading a byte, refuse any zip member whose declared uncompressed size exceeds the per-member cap before inflating it, and detect the export format and language in `archive` before `extract` runs; a rejected file returns to the file picker, and exit 4 fires only when the participant stops.
- Donate under `<session>-tiktok` with the session id generated on load, and resolve `host.donate` only on the host's `DonateSuccess`/`DonateError` reply for that key — no timeout, no synthetic result.
- The payload is every non-deleted row of every non-empty table in the desktop consent form's shape (`[{"<table id>": [...rows keyed by the extractor's raw column names, cells as strings], "deleted row count": "<n>"}]`, or `{"status": "data_submission declined"}`); windowing, search and any display bound are view-only and never reduce it.
- Exit 0 only after a successful donation or a recorded decline; every other ending exits nonzero with a fixed `info` literal (1 unhandled, 3 delivery failed, 4 upload rejected).
- `extract` must equal `tiktok.extraction()` on the committed synthetic fixtures, table by table, plus the email and own-username redaction; the fixtures are generated and their expected output regenerated by a deliberate script, never edited by hand, and real exports live only in the git-ignored `fixtures/ddp/`.
- Import nothing from `packages/feldspar`, `packages/data-collector` or `packages/python` at runtime; the only shared input is `tiktok_config.json` at build time. Keep the build free of syntax Safari 12 cannot parse: `vite build` targets `safari12` and the post-build grep for optional chaining, nullish coalescing, `import.meta` and flex `gap` must stay in CI.

## Why

The app runs on phones the Pyodide stack cannot reach, so the privacy boundaries, host-protocol contract and completion semantics that the Python records guarantee would silently lapse in this package unless restated for it; a breach here leaks participant data before consent, records a failed donation as a completion, or ships a bundle that never starts on the devices it exists for.
